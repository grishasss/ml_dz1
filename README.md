**Датасет:** Amazon Review Data (2018), **Musical Instruments, 5-core**.
[Первоисточник, описание полей и ссылки на загрузку](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/index.html).

После очистки: **219 156** уникальных взаимодействий, **27 530** пользователей,

полная категория на странице источника — 1 512 530 отзывов.

## Запуск

Python 3.13, CPU, рекомендуется 16 ГБ RAM. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/run_notebook.py
```

Основной файл — [experiments.ipynb](experiments.ipynb). Он содержит выполненные
ячейки, EDA, формулы, временное разбиение, подбор на validation, таблицы test,
графики, контрольные сравнения и выводы по вычисленным результатам.
При ручном запуске выберите ядро установленного окружения и выполните все ячейки
по порядку. Для регистрации ядра при необходимости:

```bash
python -m ipykernel install --user --name recsys-hw1 --display-name 'Recsys HW1'
```

Скрипт исполнения запускает ядро тем же Python, которым вызван; запускайте его из
активированного окружения. На первом запуске загрузчик скачает файлы
`Musical_Instruments_5.json.gz` и `meta_Musical_Instruments.json.gz` с UCSD
в игнорируемый каталог `cache/raw/`. SHA256 архивов закреплены в загрузчике,
проверяются при каждом запуске и записаны в `results/run.json`.
Сами данные, обученные модели и окружение в репозиторий не входят.

```bash
python -m pytest -q
```

## Реализация

| Файл | Метод |
|---|---|
| [models/item_knn.py](models/item_knn.py) | Item-based cosine KNN со shrinkage |
| [models/ials.py](models/ials.py) | iALS, бинарный положительный сигнал `rating >= 4` |
| [models/ease.py](models/ease.py) | EASE с ограничением нулевой диагонали |
| [models/fm.py](models/fm.py) | FM второго порядка: ID + категории + слова названия, BPR |
| [models/custom_als.py](models/custom_als.py) | ALS с собственным градуированным таргетом |

Обучение, scoring, top-K, негативный сэмплинг и метрики написаны самостоятельно.
Готовые рекомендательные алгоритмы не используются. SciPy решает линейные системы;
PyTorch предоставляет autograd и Adam для заданной в коде FM.

Для пятой модели `p* = max(0, (rating - 2) / 3)` на наблюдаемых отзывах,
на остальных парах — ноль. В базовом iALS и CustomALS **одинаковый confidence**:
`c = 1 + 20 × observed`; меняется целевая переменная. Низкие оценки включены
в наблюдаемую историю обеих моделей. Подробные формулы — в ноутбуке.

## Протокол

Глобальное временное разбиение примерно 80/10/10 с сохранением одинаковых дат
в одной части. Повторные user–item отзывы заменяются самым ранним.
Словари и полный каталог кандидатов строятся только на train; cold-start случаи
исключаются с отчётом о потерях. Для всех моделей общие пользователи каждой
части, кандидаты и исключение **всех** известных товаров, включая низкие оценки.

Основная метрика выбрана до подбора — **NDCG@10**, дополнительная — **Recall@10**.
Две конфигурации каждого метода заданы заранее в [config.json](config.json).
После выбора на validation модели заново обучаются на train+validation и один
раз оцениваются на test. Релевантность для всех методов — будущая оценка ≥4.
Seed=42, CPU, два потока; точные зависимости зафиксированы.

Дополнительные контроли: FM без метаданных и CustomALS с настройками выбранного
базового iALS. Для разностей метрик рассчитан парный bootstrap по пользователям.

## Полученные результаты

| Модель | NDCG@10 | Recall@10 |
|---|---:|---:|
| iALS | **0.017577** | 0.028193 |
| CustomALS | 0.017454 | **0.028785** |
| EASE | 0.015088 | 0.024975 |
| FM с метаданными | 0.014835 | 0.021083 |
| ItemKNN | 0.014262 | 0.022453 |

Преимущество нового таргета не подтверждено парными интервалами разностей.
Метаданные не улучшили NDCG FM и снизили Recall относительно контроля с ID.
Подробные параметры, охват каталога и ограничения интерпретации — в ноутбуке.

## Файлы результатов

- `results/validation.csv` — все проверенные конфигурации и validation-метрики.
- `results/selected.json` — выбранные до test параметры.
- `results/test.csv` — итоговые метрики, параметры и время.
- `results/controls.csv` — контрольные сравнения и 95% bootstrap-интервалы.
- `results/run.json` — конфигурация, SHA256, аудит очистки/разбиения и версии.

Ноутбук рассчитывает всё заново, не подставляя сохранённые результаты.
Точное время зависит от CPU/BLAS; EASE требует квадратичной памяти.
Ограничения warm-start оценки, смещения готового 5-core, исторического снимка
метаданных, одного seed и небольшой сетки описаны в выводах ноутбука.
